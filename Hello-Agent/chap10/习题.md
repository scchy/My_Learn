### 2.1 数据分析 MCP 服务器扩展（动手实践）🛠️

> 💡 **提示**：这是一道动手实践题，建议实际操作。

在 10.2.3 节的 MCP 服务器实现中，我们定义了 list_tools、call_tool 等核心方法。请扩展这个实现，添加一个新的 MCP 服务器，提供以下工具：

1. 数据库查询工具；
2. 数据可视化工具；
3. 报表生成工具。

要求工具之间能够协作完成复杂的数据分析任务。

```python
#!/usr/bin/env python3
"""数据分析 MCP 服务器（第十章 10.5 节风格的扩展实现）

提供三个可协作的工具，完成"查询 -> 可视化 -> 报表"数据分析流水线：
  1. query_database   - 数据库查询工具（输入 SQL，返回 JSON 行数据）
  2. visualize_data   - 数据可视化工具（消费 query_database 的输出，生成 PNG 图表）
  3. generate_report  - 报表生成工具（消费前两者输出，生成 Markdown 报表）

工具协作契约：三个工具的输入/输出均为 JSON 字符串，
前一个工具的输出可直接作为后一个工具的输入，形成处理链。
"""

import json
import os
import sqlite3
import tempfile

import matplotlib
matplotlib.use("Agg")  # 无界面环境
import matplotlib.pyplot as plt

from hello_agents.protocols import MCPServer

# ------------------------------------------------------------------
# 服务器与工作区
# ------------------------------------------------------------------
server = MCPServer(name="data-analysis-server",
                   description="数据分析服务：数据库查询 + 可视化 + 报表生成")

# 图表与报表的统一输出目录（工具间通过文件路径传递工件）
WORKSPACE = tempfile.mkdtemp(prefix="mcp_data_analysis_")


# ------------------------------------------------------------------
# 工具 1：数据库查询工具
# ------------------------------------------------------------------
def _get_connection() -> sqlite3.Connection:
    """返回带示例销售数据的内存数据库连接（生产环境替换为真实 DB 连接）。"""
    conn = sqlite3.connect(":memory:")
    conn.row_factory = sqlite3.Row
    conn.executescript("""
    CREATE TABLE sales (
        id INTEGER PRIMARY KEY,
        region TEXT NOT NULL,
        quarter TEXT NOT NULL,
        amount REAL NOT NULL
    );
    INSERT INTO sales (region, quarter, amount) VALUES
        ('华东', 'Q1', 120.5), ('华东', 'Q2', 135.2),
        ('华东', 'Q3', 148.9), ('华东', 'Q4', 172.3),
        ('华南', 'Q1',  98.3), ('华南', 'Q2', 105.7),
        ('华南', 'Q3', 122.4), ('华南', 'Q4', 131.8),
        ('华北', 'Q1',  76.9), ('华北', 'Q2',  82.1),
        ('华北', 'Q3',  91.0), ('华北', 'Q4',  99.6);
    """)
    return conn


def query_database(sql: str) -> str:
    """执行 SQL 查询并返回结构化的 JSON 数据。

    输出契约（供 visualize_data / generate_report 消费）：
      {"columns": [...], "row_count": N, "rows": [{...}, ...]}
    """
    # 只读保护：禁止写操作，避免智能体误改数据
    if any(kw in sql.upper() for kw in ("INSERT", "UPDATE", "DELETE", "DROP")):
        return json.dumps({"error": "仅支持 SELECT 查询"}, ensure_ascii=False)

    conn = _get_connection()
    try:
        rows = [dict(r) for r in conn.execute(sql).fetchall()]
        return json.dumps({
            "columns": list(rows[0].keys()) if rows else [],
            "row_count": len(rows),
            "rows": rows,
        }, ensure_ascii=False)
    except sqlite3.Error as e:
        return json.dumps({"error": f"SQL 错误: {e}"}, ensure_ascii=False)
    finally:
        conn.close()


# ------------------------------------------------------------------
# 工具 2：数据可视化工具
# ------------------------------------------------------------------
def visualize_data(data_json: str, chart_type: str = "bar",
                   x_field: str = "", y_field: str = "",
                   title: str = "Chart", group_field: str = "") -> str:
    """把 query_database 的输出渲染为 PNG 图表。

    输入契约：data_json 为 query_database 的返回值（或其 rows 部分）。
    输出契约：{"chart_path": ..., "title": ...} 供 generate_report 引用。
    """
    payload = json.loads(data_json)
    rows = payload["rows"] if isinstance(payload, dict) and "rows" in payload else payload
    if not rows:
        return json.dumps({"error": "没有可可视化的数据"}, ensure_ascii=False)

    fig, ax = plt.subplots(figsize=(8, 5))
    if group_field:  # 分组对比，如 region(quarter, amount)
        groups = sorted({r[group_field] for r in rows})
        series = sorted({r[x_field] for r in rows})
        width = 0.8 / len(series)
        for i, s in enumerate(series):
            vals = [next((r[y_field] for r in rows
                          if r[group_field] == g and r[x_field] == s), 0)
                    for g in groups]
            ax.bar([p + i * width for p in range(len(groups))], vals, width, label=str(s))
        ax.set_xticks([p + width * (len(series) - 1) / 2 for p in range(len(groups))])
        ax.set_xticklabels(groups)
        ax.legend(title=x_field)
    else:
        xs, ys = [r[x_field] for r in rows], [r[y_field] for r in rows]
        ax.plot(xs, ys, marker="o") if chart_type == "line" else ax.bar(xs, ys)
    ax.set_title(title)
    ax.set_ylabel(y_field)

    safe = "".join(c if c.isalnum() else "_" for c in title)
    path = os.path.join(WORKSPACE, f"{safe}.png")
    fig.tight_layout()
    fig.savefig(path, dpi=120)
    plt.close(fig)  # 释放内存，支持长流水线

    return json.dumps({"chart_path": path, "title": title,
                       "rows_visualized": len(rows)}, ensure_ascii=False)


# ------------------------------------------------------------------
# 工具 3：报表生成工具
# ------------------------------------------------------------------
def generate_report(data_json: str, chart_json: str, title: str,
                    summary: str = "") -> str:
    """汇总数据明细与图表，生成 Markdown 报表文件。

    输入契约：
      data_json  - query_database 的输出；
      chart_json - visualize_data 的输出（可传 "{}" 表示无图表）。
    输出契约：{"report_path": ..., "title": ...}
    """
    payload = json.loads(data_json)
    rows = payload["rows"] if isinstance(payload, dict) and "rows" in payload else payload
    cols = payload.get("columns") or (list(rows[0].keys()) if rows else [])

    chart = json.loads(chart_json) if chart_json else {}

    lines = [f"# {title}", ""]
    if summary:
        lines += [f"> {summary}", ""]
    lines += [f"共分析 **{len(rows)}** 条数据记录。", "", "## 数据明细", "",
              "| " + " | ".join(cols) + " |", "|" + "---|" * len(cols)]
    for r in rows:
        lines.append("| " + " | ".join(str(r.get(c, "")) for c in cols) + " |")
    if chart.get("chart_path"):
        lines += ["", "## 图表", "",
                  f"![{chart.get('title', 'chart')}]({chart['chart_path']})"]
    lines += ["", "---", "*Report generated by DataAnalysis MCP Server*"]

    safe = "".join(c if c.isalnum() else "_" for c in title)
    path = os.path.join(WORKSPACE, f"{safe}.md")
    with open(path, "w", encoding="utf-8") as f:
        f.write("\n".join(lines))

    return json.dumps({"report_path": path, "title": title,
                       "sections": 3 if chart else 2}, ensure_ascii=False)


def get_server_info() -> str:
    """获取服务器信息。"""
    info = {"name": "DataAnalysis MCP Server",
            "version": "1.0.0",
            "workspace": WORKSPACE,
            "pipeline": "query_database -> visualize_data -> generate_report",
            "tools": ["query_database", "visualize_data", "generate_report"]}
    return json.dumps(info, ensure_ascii=False, indent=2)


# 注册工具到服务器
server.add_tool(query_database)
server.add_tool(visualize_data)
server.add_tool(generate_report)
server.add_tool(get_server_info)


if __name__ == "__main__":
    server.run()
```


### 2.2 Resources 与 Prompts 的应用设计

MCP 协议支持"资源"（Resources）和"提示"（Prompts）两个重要概念，但本章主要聚焦于"工具"（Tools）。请查阅 MCP 官方文档，了解 Resources 和 Prompts 的设计目的，并设计一个应用场景，展示如何利用这三个核心概念构建更强大的智能体系统。

- Prompts 管入口：把用户意图、必填参数、输出模板、证据要求标准化；新值班同学也能得到一致流程。
- Resources 管证据：以 URI 引用可审计、可缓存、可订阅更新的上下文；避免每次让工具返回冗余全文，也便于最小权限。
- Tools 管动作：只在需要时执行，且副作用通过 human-in-the-loop 收口；工具结果还能回链资源，形成“证据—动作—复盘”闭环。


可以把它们对比成：  
- Tools = 函数签名/执行能力：告诉模型每个工具叫什么、输入 schema、输出大概是什么，模型据此决定何时 tools/call。
- Prompts = 用户可点选的任务模板/SOP：把“遇到这类事该怎么问、先查什么、再做什么、禁用什么、输出成什么样”固化下来。官方设计里 

Prompts 是 user-controlled，典型入口是 slash command / 模板选择；模型负责在模板展开后继续推理和调工具。 
也就是说，tools schema 让模型“会调工具”，prompts 让模型“别自由发挥”。

所以设计 MCP server 时，一个实用分工是：
- 工具描述写清楚单个动作能力；
- prompt 写清楚多工具编排逻辑、边界、验收格式；
- resource 提供证据与只读上下文。

一句话：tools 是“可调用的能力”，prompts 是“用户认可的作业指导书”；agent 真正变强，靠的是把指导书、证据资源、可审计工具调用串成闭环。

### 3.2 冲突解决机制设计

A2A 协议定义了 task、task_result 等消息类型。请分析：如果协作过程中出现冲突（如两个智能体对同一问题有不同意见），应该如何设计冲突解决机制？请扩展 A2A 协议，添加"协商"（negotiation）和"投票"（voting）等消息类型。

| 组别   | 消息类型                  | 方向           | 语义                           |
| ---- | --------------------- | ------------ | ---------------------------- |
| 冲突检测 | `conflict_detected`   | result → 协调器 | 两个 `task_result` 结论不一致，触发流水线 |
| 协商   | `negotiation_propose` | 双向交替         | 提案：立场 + 置信度 + 证据             |
|      | `negotiation_accept`  | 响应方 → 提案方    | 接受 → 共识达成，流水线结束              |
|      | `negotiation_counter` | 响应方 → 提案方    | 反提案：自己的立场 + 让步邀请             |
|      | `negotiation_reject`  | 任意方          | 拒绝退出双边协商 → 转投票               |
| 投票   | `vote_request`        | 协调器 → 全体     | 发起投票：议题 + 选项 + 规则 + 法定人数     |
|      | `vote_ballot`         | 投票者 → 协调器    | 选票：选择 + 理由（理由留作审计）           |
|      | `vote_result`         | 协调器 → 全体     | 计票结果；含平票/未达法定人数标记            |
| 升级   | `escalation`          | 协调器 → 人工/仲裁  | 附上冲突全程日志，等待最终裁决              |


```
task_result A ──┐
                ├─① 冲突检测──结论不同？──是──┐
task_result B ──┘                            ▼
                    ② 双边协商（≤N轮，置信度差<阈值即接受）
                       │达成                │破裂（拒接/轮数耗尽）
                       ▼                    ▼
                 共识达成✓            ③ 群体投票（加权计票+法定人数）
                                          │有胜负           │平票/未达法定人数
                                          ▼                  ▼
                                    采纳多数意见✓      ④ 升级 → 人工/仲裁智能体
```

三个关键机制细节：
- 协商让步逻辑：智能体收到提案时比较双方置信度，差距小于容忍阈值（默认 0.2）则接受；否则反提案。收到反提案时再判断一次，仍不一致则拒绝退出——保证最多 2N 条消息必然出结果；
- 投票加权：不同智能体权重不同（如专家智能体 2.0、普通 1.0），支持加权多数制；投票前先检查法定人数，避免少数派擅自定夺；
- 平票兜底：最高票并列时不能直接随机选一个（涉及可信决策），必须升级。


沙箱实测三个场景，全部符合预期：
- 场景 1（置信度 0.85 vs 0.80）：第 1 轮即达成协商 —— {'resolution': 'negotiation', 'rounds': 1}
- 场景 2（双方固执 + 5 个评审加权投票 4.5:2.0）：协商破裂后投票采纳"方案X" —— {'resolution': 'vote', 'winner': '方案X'}
- 场景 3（4 个评审 2:2 平票）：升级到人工 —— {'resolution': 'escalation', 'reason': '平票 ...', 'escalate_to': 'human'}

```python
#!/usr/bin/env python3
"""A2A 协议冲突解决扩展：协商（Negotiation）与投票（Voting）消息类型

对应第十章习题 3 第 2 问。在 A2A 原生 task / task_result 之上，
新增四级冲突解决流水线：检测 → 协商 → 投票 → 升级。

映射到 HelloAgents A2AServer 的方式（与 10.3 节 negotiate/propose skill 风格一致）：

    from hello_agents.protocols import A2AServer

    agent = A2AServer(name="reviewer", description="评审智能体")

    @agent.skill("propose")
    def on_propose(text: str) -> str:
        msg = Message(MsgType.NEGOTIATION_PROPOSE, "reviewer", "*",
                      json.loads(text))
        reply = resolver_or_agent.handle(msg)
        return json.dumps(asdict(reply), ensure_ascii=False)

    # 协商、投票、升级分别注册为 negotiate / vote / escalate 技能，
    # 由 A2A 消息传递载体，由 ConflictResolver 作为协调者驱动状态机。
"""

import json
import time
import uuid
from dataclasses import dataclass, field, asdict
from enum import Enum
from typing import Any, Callable, Dict, List, Optional


# ================= A2A 扩展消息类型 =================
class MsgType(str, Enum):
    # ---- 原生类型（A2A 已有） ----
    TASK = "task"
    TASK_RESULT = "task_result"
    # ---- 冲突解决扩展 ----
    CONFLICT_DETECTED = "conflict_detected"       # 冲突检测报告
    NEGOTIATION_PROPOSE = "negotiation_propose"   # 协商提案（含立场+置信度+证据）
    NEGOTIATION_ACCEPT = "negotiate_accept"       # 接受提案 → 共识达成
    NEGOTIATION_COUNTER = "negotiate_counter"     # 反提案（附理由与让步条件）
    NEGOTIATION_REJECT = "negotiate_reject"       # 拒绝并退出双边协商
    VOTE_REQUEST = "vote_request"                 # 发起投票（含议题/选项/规则）
    VOTE_BALLOT = "vote_ballot"                   # 选票（含选择与理由）
    VOTE_RESULT = "vote_result"                   # 计票结果（含平票标记）
    ESCALATION = "escalation"                     # 升级：转人工或仲裁智能体


@dataclass
class Message:
    msg_type: MsgType
    sender: str
    recipient: str
    payload: Dict[str, Any]
    round: int = 0
    msg_id: str = field(default_factory=lambda: uuid.uuid4().hex[:8])
    timestamp: float = field(default_factory=time.time)

    def to_json(self) -> str:
        return json.dumps({**asdict(self), "msg_type": self.msg_type.value},
                          ensure_ascii=False)


# ================= 智能体与策略 =================
class Agent:
    """持有立场的智能体，同一策略可复用于协商响应与投票响应。"""
    def __init__(self, name: str, strategy: Callable[[Message], Optional[Message]]):
        self.name = name
        self.strategy = strategy

    def handle(self, msg: Message) -> Optional[Message]:
        return self.strategy(msg)


def compromising_strategy(agent_name: str, confidence: float,
                          tolerance: float = 0.2) -> Callable:
    """协商策略：置信度差 < tolerance 则接受（让步），否则反提案；
    收到反提案时再判断一次，仍不一致则拒绝退出——保证协商必然终止。"""
    def strategy(msg: Message) -> Optional[Message]:
        if msg.msg_type == MsgType.NEGOTIATION_PROPOSE:
            if abs(confidence - msg.payload["confidence"]) < tolerance:
                return Message(MsgType.NEGOTIATION_ACCEPT, agent_name, msg.sender,
                               {"reason": "置信度接近，接受提案"}, round=msg.round)
            return Message(MsgType.NEGOTIATION_COUNTER, agent_name, msg.sender,
                           {"claim": f"{agent_name}的观点", "confidence": confidence,
                            "reason": "请重新评估"}, round=msg.round)
        if msg.msg_type == MsgType.NEGOTIATION_COUNTER:
            if abs(confidence - msg.payload["confidence"]) < tolerance:
                return Message(MsgType.NEGOTIATION_ACCEPT, agent_name, msg.sender,
                               {"reason": "接受反提案"}, round=msg.round)
            return Message(MsgType.NEGOTIATION_REJECT, agent_name, msg.sender,
                           {"reason": "无法达成一致"}, round=msg.round)
        if msg.msg_type == MsgType.VOTE_REQUEST:
            return Message(MsgType.VOTE_BALLOT, agent_name, "conflict_resolver",
                           {"choice": msg.payload.get("my_option", "abstain"),
                            "reason": f"{agent_name}的立场票"})
        return None
    return strategy


def stubborn_strategy(agent_name: str) -> Callable:
    """协商策略：绝不接受，强制流水线进入投票阶段。"""
    def strategy(msg: Message) -> Optional[Message]:
        if msg.msg_type in (MsgType.NEGOTIATION_PROPOSE, MsgType.NEGOTIATION_COUNTER):
            return Message(MsgType.NEGOTIATION_REJECT, agent_name, msg.sender,
                           {"reason": "坚持己见"}, round=msg.round)
        return None
    return strategy


# ================= 冲突协调器：四级流水线 =================
class ConflictResolver:
    """检测 → 协商 → 投票 → 升级。每级失败自动降级到下一级，全部失败则升级。"""

    def __init__(self, max_negotiation_rounds: int = 3,
                 quorum: float = 0.6, arbiter: str = "human"):
        self.max_rounds = max_negotiation_rounds   # 协商轮数上限（防死循环）
        self.quorum = quorum                        # 投票法定人数比例
        self.arbiter = arbiter                      # 升级目标：human / 仲裁智能体名
        self.log: List[Message] = []                # 全量消息留痕（可审计）

    # 第 1 级：冲突检测（真实场景可替换为规则引擎或 embedding 相似度）
    @staticmethod
    def detect(result_a: Dict, result_b: Dict) -> bool:
        return result_a.get("conclusion") != result_b.get("conclusion")

    # 第 2 级：双边协商
    def negotiate(self, a: Agent, b: Agent, init_claim: Dict) -> Optional[Dict]:
        proposer, responder = a, b
        proposal = Message(MsgType.NEGOTIATION_PROPOSE, a.name, b.name,
                           {"claim": init_claim["conclusion"],
                            "confidence": init_claim["confidence"],
                            "evidence": init_claim.get("evidence", "")})
        for rnd in range(1, self.max_rounds + 1):
            proposal.round = rnd
            self.log.append(proposal)
            reply = responder.handle(proposal)
            self.log.append(reply)
            if reply.msg_type == MsgType.NEGOTIATION_ACCEPT:
                return {"resolution": "negotiation",
                        "consensus": f"采纳 {proposer.name} 第{rnd}轮提案",
                        "rounds": rnd}
            if reply.msg_type == MsgType.NEGOTIATION_REJECT:
                return None
            proposer, responder = responder, proposer
            proposal = Message(MsgType.NEGOTIATION_PROPOSE, proposer.name,
                               responder.name,
                               {"claim": reply.payload["claim"],
                                "confidence": reply.payload["confidence"],
                                "evidence": reply.payload.get("reason", "")})
        return None  # 轮数耗尽，协商破裂

    # 第 3 级：群体投票
    def vote(self, question: str, ballots: List[Message],
             weights: Optional[Dict[str, float]] = None) -> Dict:
        weights = weights or {}
        tally: Dict[str, float] = {}
        for b in ballots:
            tally[b.payload["choice"]] = tally.get(b.payload["choice"], 0.0) \
                                         + weights.get(b.sender, 1.0)
        total_weight = sum(weights.values()) or len(ballots)
        voted_weight = sum(weights.get(b.sender, 1.0) for b in ballots)
        if voted_weight < self.quorum * total_weight:
            return {"resolution": "escalation", "reason": "未达法定人数",
                    "tally": tally, "escalate_to": self.arbiter}
        ranked = sorted(tally.items(), key=lambda kv: kv[1], reverse=True)
        if len(ranked) > 1 and ranked[0][1] == ranked[1][1]:
            return {"resolution": "escalation", "reason": f"平票 {dict(tally)}",
                    "tally": tally, "escalate_to": self.arbiter}
        return {"resolution": "vote", "winner": ranked[0][0],
                "tally": tally, "question": question}

    # 第 4 级：升级
    @staticmethod
    def escalate(reason: str, to: str) -> Message:
        return Message(MsgType.ESCALATION, "conflict_resolver", to,
                       {"reason": reason, "action": "等待人工/仲裁裁决"})

    # 总控：协商失败 → 投票；平票/未达法定人数 → 升级
    def resolve(self, a: Agent, b: Agent, init_claim: Dict,
                question: str = "",
                electorate: Optional[List[Agent]] = None,
                weights: Optional[Dict[str, float]] = None) -> Dict:
        outcome = self.negotiate(a, b, init_claim)
        if outcome:
            return outcome
        if electorate:
            req = Message(MsgType.VOTE_REQUEST, "conflict_resolver", "*",
                          {"question": question or init_claim["conclusion"]})
            self.log.append(req)
            ballots = [agent.handle(req) for agent in electorate]
            ballots = [x for x in ballots if x and x.msg_type == MsgType.VOTE_BALLOT]
            outcome = self.vote(question or init_claim["conclusion"], ballots, weights)
            self.log.append(Message(MsgType.VOTE_RESULT, "conflict_resolver",
                                    "*", outcome))
        if outcome["resolution"] == "escalation":
            self.log.append(self.escalate(outcome["reason"],
                                          outcome["escalate_to"]))
        return outcome


# ================= 演示：三个场景 =================
if __name__ == "__main__":
    # 场景 1：协商收敛
    r = ConflictResolver()
    a = Agent("研究员A", compromising_strategy("研究员A", 0.85))
    b = Agent("研究员B", compromising_strategy("研究员B", 0.80))
    print("场景1:", r.resolve(a, b, {"conclusion": "方案X更优", "confidence": 0.85}))

    # 场景 2：协商破裂 → 加权投票
    r2 = ConflictResolver(max_negotiation_rounds=2)
    sa = Agent("固执A", stubborn_strategy("固执A"))
    sb = Agent("固执B", stubborn_strategy("固执B"))
    voters = [Agent(f"评审{i}",
                    (lambda n, c: (lambda m: Message(
                        MsgType.VOTE_BALLOT, n, "conflict_resolver",
                        {"choice": c, "reason": n})(m) if m.msg_type
                        == MsgType.VOTE_REQUEST else None))(f"评审{i}",
                        "方案X" if i < 3 else "方案Y"))
              for i in range(5)]
    weights = {"评审0": 2.0, "评审1": 1.5, "评审2": 1.0, "评审3": 1.0, "评审4": 1.0}
    print("场景2:", r2.resolve(sa, sb, {"conclusion": "方案X", "confidence": 0.9},
                               question="选方案X还是方案Y？",
                               electorate=voters, weights=weights))

    # 场景 3：投票平票 → 升级人工
    r3 = ConflictResolver(max_negotiation_rounds=1)
    voters3 = [Agent(f"评审{i}",
                     (lambda n, c: (lambda m: Message(
                         MsgType.VOTE_BALLOT, n, "conflict_resolver",
                         {"choice": c, "reason": n})(m) if m.msg_type
                         == MsgType.VOTE_REQUEST else None))(f"评审{i}",
                         "方案X" if i % 2 == 0 else "方案Y"))
               for i in range(4)]
```

#### Grok Bot多agent的实现

而在 **Grok Bot / OpenMausBot** 这类原生多 Agent 桌面工作台中，所有 Bot 均运行在**同一个宿主进程（或同一套受控沙箱集群）**内。为了消除跨网通信延迟与繁琐的协议序列化开销，它们放弃了重型的标准 A2A 协议，转而采用：
> **“应用内消息总线（In-App Message Bus）+ 角色描述即工具（Agent-as-a-Tool）+ 频道级共享工作区（Shared Workspace）”** 的极简内聚架构。

| 对比维度 | 标准 A2A 协议 (Google 等) | Grok Bot / OpenMausBot 内部交互架构 |
| :--- | :--- | :--- |
| **适用边界** | 跨组织、跨网络的异构分布式 Agent 互联 | 同宿主/同工作台内的私有“数字员工团队”协同 |
| **能力发现机制** | 远程拉取 JSON 格式的 `Agent Card` | 直接读取本地数据库中的 `Name + Title + Description` |
| **通信传输层** | HTTP / SSE + JSON-RPC 2.0 网络请求 | 宿主进程内存事件队列 + 本地 `NDJSON` / SQLite 消息流 |
| **上下文与文件传递** | 需将文件编码为 Payload 或通过外部 URL 传输 | **零拷贝**：直接共享频道对话流与本地 `Working Folder` |
| **外部生态扩展** | A2A（找其他 Agent）+ MCP（调工具） | 对内极简总线（管团队）+ 对外标准 **MCP**（接工具） |

## 5. 安全性与隐私保护 ⭐⭐⭐ 理论/设计

智能体通信协议的安全性和隐私保护是实际应用中的关键问题。请思考：

### 5.1 MCP 权限控制机制

在 10.2.4 节的 MCP 客户端实现中，智能体可以调用 MCP 服务器提供的任何工具。请分析：这种设计存在什么安全风险？如果 MCP 服务器提供了危险操作（如删除文件、执行系统命令），应该如何设计权限控制机制？

LLM 会被提示注入劫持、幻觉触发不可逆操作，且 MCP 服务器可能来自不可信供应链。权限控制应采用五层纵深防御：能力最小化白名单、工具风险分级与默认拒绝策略、参数级沙箱（路径禁闭 + 命令注入拦截）、危险操作人工审批加一次性令牌、身份认证与全量审计。参考实现已验证 8 个场景，路径穿越、命令注入、未审批删除、令牌复用均被正确拦截。

| 场景                           | 结果                       |
| ---------------------------- | ------------------------ |
| ① 安全工具 `add`                 | 自动放行                     |
| ② 路径穿越 `../../../etc/passwd` | 拦截：路径越界                  |
| ③ 工作区内写文件                    | 放行（受禁闭约束）                |
| ④ 命令注入 `echo hi; rm -rf /`   | 拦截：命令被策略拦截               |
| ⑤ 删除文件无审批                    | 挂起，返回 `pending_approval` |
| ⑥ 管理员拒绝后重试                   | 仍挂起，不可执行                 |
| ⑦ 批准 + 令牌执行 / 令牌复用           | 放行一次；复用失效，重新挂起           |
| ⑧ 未知工具 `format_disk`         | 默认拒绝                     |
